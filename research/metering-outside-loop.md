# Metering Anthropic spend outside the loop (ticket #55)

Question: can spend by pi (API key) and Claude Code (subscription or API key) in a sandbox be attributed to the instance budget, through Admin API reports, per-sandbox keys or workspaces, or egress-proxy parsing; what hard per-thread caps and kill switches exist; how do subscription runs get shown to the operator.

Researched 2026-10-17. Builds on [#32 pi-claude-code-sandbox](https://github.com/jeiang/atrium/blob/research/pi-claude-code-sandbox/research/pi-claude-code-sandbox.md), [#25 egress-proxy](https://github.com/jeiang/atrium/blob/research/egress-proxy/research/egress-proxy.md), [#26 claude-models](https://github.com/jeiang/atrium/blob/research/claude-models/research/claude-models.md), [#34 auth](https://github.com/jeiang/atrium/blob/research/auth-notion-github-grafana-anthropic/research/auth-notion-github-grafana-anthropic.md) and [#53 anthropic-go-sdk](https://github.com/jeiang/atrium/blob/research/anthropic-go-sdk/research/anthropic-go-sdk.md); those are not repeated. Atrium facts cite `path:line` at origin/main c221de8. `[inference]` marks my reasoning, `[unverified]` marks things I could not confirm in a primary source.

## 1. Answer in brief

1. **Admin API reports are a reconciliation source, not a metering source.** Usage report: `1m`/`1h`/`1d` buckets (max 1,440 / 168 / 31 buckets), groupable by `api_key_id`, `workspace_id`, `model`, `service_tier`, `speed`, `context_window`, `inference_geo`, `account_id`, `service_account_id`; data "typically appears within 5 minutes", recommended polling at most once per minute ([Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api), [usage_report reference](https://platform.claude.com/docs/en/api/beta/organization/usage_report/retrieve_messages)). Cost report: `1d` buckets only, groupable only by `workspace_id` and `description` (not by key), cents as decimal strings; Priority Tier is absent from it; code execution only appears there ([cost_report reference](https://platform.claude.com/docs/en/api/beta/organization/cost_report/retrieve)). Nothing is per request or per thread. It needs an Admin credential and an organization (unavailable to individual accounts) ([Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)).
2. **Per-sandbox keys or workspaces are not possible.** The Admin API cannot create API keys ([Admin API FAQ](https://platform.claude.com/docs/en/manage-claude/admin-api)); workspaces can be created by API but a workspace's spend limit is set only in the Console, and the default workspace cannot have limits ([Workspaces](https://platform.claude.com/docs/en/manage-claude/workspaces#setting-workspace-limits)); max 100 workspaces per org by default. What is possible: one key (or one multi-workspace key) per instance, plus a fixed small set of workspaces (for example `atrium-<instance>` and `atrium-sandbox-<instance>`) selected by the `anthropic-workspace-id` request header, which a gateway can set ([Workspaces: key scoping](https://platform.claude.com/docs/en/manage-claude/workspaces#api-keys-and-resource-scoping)).
3. **The system of record for sandbox API spend should be the atrium-hosted gateway** (#25 section 5.2), parsing `usage` from every response. Anthropic returns the workspace on every response in the `anthropic-workspace-id` header and the request in `request-id` ([Workspaces](https://platform.claude.com/docs/en/manage-claude/workspaces#identify-the-workspace-behind-an-api-response)), so each ledger row can be tied back to Anthropic's records. The parser must follow the iteration and cumulative-usage rules in section 4; today's atrium code already misses one of them (section 4.1).
4. **Hard per-thread caps exist only on our side** (gateway admission with reservations, revoking the per-sandbox bearer, suspending the microVM) plus client flags (`--max-budget-usd`, `--max-turns`, pi `abort`). Anthropic-side limits are monthly and per workspace or org, enforced as HTTP 400 `invalid_request_error` ([errors](https://platform.claude.com/docs/en/api/errors), [rate limits](https://platform.claude.com/docs/en/api/rate-limits#setting-your-own-spend-limit)); useful as a backstop only.
5. **Subscription Claude Code runs cannot be metered or capped by atrium in dollars.** They can be shown as "not billed to the budget" with: per-run `result` totals (API-list-price equivalents) and `rate_limit_event` plan utilization from the stream adapter, optionally per-request OpenTelemetry events from the VM to an atrium-hosted OTLP receiver. There is no public API for an individual Pro/Max account's usage; the Enterprise Analytics API is Enterprise-only ([Analytics APIs](https://platform.claude.com/docs/en/manage-claude/analytics-api)).

## 2. Admin API: what it gives, what it cannot

### 2.1 Credentials and availability
- Admin API key (`sk-ant-admin...`), an `org:admin` OAuth token, or a personal/service-account key not scoped to a workspace; workspace keys do not work. Individual accounts have no Admin API; they must create an organization ([Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)). `[inference]` Many self-hosters (single owner, personal Console) will have neither, so reconciliation must be optional and the gateway ledger must stand alone.
- Claude Platform on AWS: usage/cost endpoints are not available ([same page](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)). Claude Enterprise orgs use the Analytics API with a different key ([same page](https://platform.claude.com/docs/en/manage-claude/usage-cost-api#which-api-do-you-need)).

### 2.2 Granularity and latency (table)

| | Usage report `/v1/organizations/usage_report/messages` | Cost report `/v1/organizations/cost_report` |
|---|---|---|
| Buckets | `1m` (default 60, max 1,440), `1h` (24 / 168), `1d` (7 / 31) | `1d` only |
| Group by | `api_key_id`, `workspace_id`, `model`, `service_tier`, `speed`, `context_window`, `inference_geo`, `account_id`, `service_account_id` | `workspace_id`, `description` (description adds parsed `model`, `token_type`, `service_tier`, `speed`, `cost_type`, `context_window`) |
| Fields | `uncached_input_tokens`, `cache_creation.{ephemeral_5m,ephemeral_1h}_input_tokens`, `cache_read_input_tokens`, `output_tokens`, `server_tool_use` | `amount` (cents, decimal string), `currency` (USD), `cost_type` in `tokens`, `web_search`, `code_execution`, `session_usage` |
| Excludes | code execution | Priority Tier; per-key split |
| Freshness | typically within 5 minutes, "occasionally longer"; poll at most 1/min | same |
| Null ids | `workspace_id` null for the default workspace; `api_key_id` null for Console playground | same for `workspace_id` |

Sources: [usage_report](https://platform.claude.com/docs/en/api/beta/organization/usage_report/retrieve_messages), [cost_report](https://platform.claude.com/docs/en/api/beta/organization/cost_report/retrieve), [FAQ](https://platform.claude.com/docs/en/manage-claude/usage-cost-api#frequently-asked-questions).

Consequences:
- Per-thread or per-run attribution is impossible from Anthropic's side; `metadata.user_id` is not a report dimension (not in the group_by list).
- Per-key dollars need `usage_report` x our rate table; the cost report cannot split by key. With one dedicated workspace per purpose, `workspace_id` is enough.
- Months: Anthropic's tier cap resets at 00:00 UTC on the first of the month ([rate limits](https://platform.claude.com/docs/en/api/rate-limits#reaching-your-spend-cap)); atrium's month starts at local midnight (`src/atrium/agent/usage.py:69-71` uses `TIMEZONE`). `[inference]` Store UTC timestamps and compute reconciliation windows in UTC; keep the user-facing budget month in local time but show the boundary mismatch.
- Because buckets can be `1h`, the useful check is token-exact, not dollar-approximate: sum the ledger per (hour, model, key/workspace) and compare integer token fields with the usage report after a 15-minute settling lag `[inference]`. Differences have known causes: client-aborted streams, fallback credit ([fallback credit](https://platform.claude.com/docs/en/build-with-claude/fallback-credit)), non-gateway traffic using the same key, billed refusals ([refusals billing](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)).

### 2.3 Reconciliation design (optional feature)
- Settings: optional Admin key (stored separately, "high privilege", never in tool results or the VM; #34 section 5), `reconcile_workspace_ids`.
- Job every 10 to 60 minutes: list closed hourly buckets for the last 48 h, compare with ledger, store `reconcile` rows (bucket, ledger tokens, Anthropic tokens, delta, cause guess). Daily: compare month-to-date `cost_report` (divide `amount` by 100) with the ledger total.
- Drift handling: show it; offer a one-click "true-up" that writes a `kind='reconcile'` adjustment row so the budget gate matches the invoice. `[inference]` Never auto-correct silently; the Admin figure excludes Priority Tier and the cost report may be revised for the current day.
- Alert (ntfy) on unattributed spend: Anthropic tokens in the instance's workspace with no ledger rows means a key leak or bypass of the gateway.

|---|---|---|---|
| A. Gateway ledger keyed by per-sandbox bearer | exact (thread, run, agent) | yes | #25 section 5.2. Bearer maps to sandbox id; Claude Code also sends `x-claude-code-session-id`, `x-claude-code-agent-id`, `x-claude-code-parent-agent-id`, `x-claude-code-request-class` (`main`/`subagent`/`workflow`/`compaction`/`auxiliary`), `x-claude-code-prompt-id`, which the gateway "may consume for routing, attribution, and tracing" ([gateway protocol: request headers](https://code.claude.com/docs/en/llm-gateway-protocol#request-headers)). pi sends no such headers that I found `[unverified]`; the bearer suffices. |
| B. One key per sandbox | exact via `api_key_id` | **no** | Keys cannot be created through the API ([Admin API FAQ](https://platform.claude.com/docs/en/manage-claude/admin-api)); 1 key per thread would also need manual Console work. |
| C. One workspace per sandbox/thread | via `workspace_id` | **no** | Needs a key per workspace (B), spend limit UI-only, 100 workspace cap, caches are isolated per workspace so every thread would lose cache sharing ([Workspaces note](https://platform.claude.com/docs/en/manage-claude/workspaces#api-keys-and-resource-scoping)). Archiving a workspace archives its keys. |
| D. Fixed workspaces per purpose, selected by header | per purpose, not per thread | yes | A multi-workspace personal/service-account key runs in the workspace named by `anthropic-workspace-id` ([Workspaces](https://platform.claude.com/docs/en/manage-claude/workspaces#api-keys-and-resource-scoping)); the gateway sets it. Gives separate Admin lines, separate Console spend limit (backstop) and rate-limit overrides ([Workspaces: limits](https://platform.claude.com/docs/en/manage-claude/workspaces#set-workspace-limits)) for loop vs sandbox spend. Requires an org and a multi-workspace key `[inference]` (a single-workspace key cannot switch). Optional hardening. |
| E. Admin report only | per key/workspace, 5+ min late | partial | Reconciliation only (section 2). |

Recommendation: A as the metering source of truth; D as an optional owner-side backstop (sandbox workspace with a Console spend limit equal to the sandbox share of the budget); E as optional reconciliation. Never rely on B or C.

## 4. Proxy-side usage parsing (the part that must be exact)

### 4.1 What the existing code gets wrong and the port must not copy
`usage.record` reads only top-level `input_tokens`, `output_tokens`, cache fields and `server_tool_use` (`src/atrium/agent/usage.py:20-35,38-65`); `loop.py:386-390` calls it with `field(response, "usage")`. With the compaction beta enabled (`COMPACT = "compact_20260112"`, `src/atrium/agent/context.py:32`), Anthropic states the top-level `input_tokens`/`output_tokens` "do not include compaction iteration usage" and every response then carries `usage.iterations`; to bill correctly "sum across all entries in the `usage.iterations` array" ([compaction at a token threshold: understanding usage](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold#understanding-usage)). So a request that triggers server compaction under-reports by the compaction iteration (the summarizer reads the whole context; the doc's own example shows 180,000 input tokens for it). `[inference]` the budget has been under-counting these; candidate fix for Phase A (ticket 1 below). The `usage` table also has no model column that drives pricing (`pricing.py:1-23` is Haiku-only; #26 section 6).

### 4.2 Parsing rules (spec for the gateway and for the Go adapter)

1. **Streaming**: `message_start.message.usage` carries input and cache fields and a placeholder `output_tokens`; `message_delta.usage` is **cumulative** ([streaming](https://platform.claude.com/docs/en/build-with-claude/streaming#event-types)). A `message_delta` may carry only `output_tokens` (doc example), or also `input_tokens`, cache fields and `server_tool_use` (web-search example in the same page). Rule: start from `message_start.usage`, then for each `message_delta` overwrite each field that is present and non-null; never add. This is what the SDK does: `output_tokens` always, the others only when valid, plus `server_tool_use`, `output_tokens_details`, `fallback_credit`, `iterations` ([`betamessageutil.go` v1.82.0, lines 39-62](https://raw.githubusercontent.com/anthropics/anthropic-sdk-go/v1.82.0/betamessageutil.go)). That code does not copy `cache_creation` (the 5m/1h split) from a delta; a gateway that cares about the split should keep the `message_start` split and recompute if a delta ever carries one `[unverified: whether deltas carry it]`.
2. **Iterations**: when `usage.iterations` is present, bill from it and ignore the top-level totals. Each entry has `type` and its own `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `cache_creation{5m,1h}`. Types in the reference: `message`, `compaction`, `advisor_message`, `fallback_message` ([Messages API: usage.iterations](https://platform.claude.com/docs/en/api/beta/messages/create)). Top-level fields mean different things per feature: with compaction they exclude the compaction entry; with the advisor tool they hold executor tokens only because the advisor runs "at the advisor model's rates"; with server-tool loops each top-level field is "the sum of that field across all executor iterations" ([advisor tool: usage and billing](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool#usage-and-billing)). Summing iterations plus top-level would double count; summing only the top level undercounts. Price each entry by its own `model` when present (`advisor_message`, `fallback_message`, `message`), else the request model (`compaction` has no `model`).
3. **Iterations in a stream**: the advisor page says a `message_delta` "follows with the updated `usage.iterations` array" ([advisor](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool)); the SDK copies `iterations` from deltas (line 61-62 above). I found no doc sentence that threshold-compaction streams do the same `[unverified]`; the recorded-fixture test (candidate ticket 4) must capture one.
4. **Compaction in streams** arrives as one `content_block_delta` with the full summary ([threshold: streaming](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold#streaming)); it does not change usage parsing. A paused compaction returns `stop_reason: "compaction"`. On-demand compaction (`compact-2026-09-04`) returns zero top-level tokens and reports everything in `iterations` ([compaction on demand: count usage](https://platform.claude.com/docs/en/build-with-claude/compaction-on-demand#count-compaction-usage)); same rule.
5. **Claude Code's own client compaction** is an ordinary request tagged `x-claude-code-request-class: compaction` (and `x-claude-code-compaction: auto|manual|reactive`) ([gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol#request-headers)); meter it normally, label it in the ledger.
6. **Server tools**: web search is billed per request at $10 per 1,000 plus tokens ([pricing](https://platform.claude.com/docs/en/about-claude/pricing#web-search-tool)); count `usage.server_tool_use.web_search_requests` (already modelled at `usage.py:34-35`, `pricing.py:5`). Web fetch has no extra charge; code execution container time is billed separately and appears only in the cost report, not usage, so it cannot be metered at the gateway (moot in Phase B because the sandbox replaces it, but Claude Code in the VM never uses Anthropic's container).
7. **Price modifiers carried in usage**: `service_tier` (`standard`/`priority`/`batch`), `speed` (`fast` costs a premium: Opus 5.5 $8/$40 per MTok), `inference_geo: "us"` multiplies every category by 1.1 ([pricing](https://platform.claude.com/docs/en/about-claude/pricing#fast-mode-pricing)). Haiku 5.5 bills a per-request tier on total prompt tokens including cache reads and writes (>100,000 is the higher price) ([pricing: long context](https://platform.claude.com/docs/en/about-claude/pricing#long-context-pricing)); `tier_of` already does this per call (`pricing.py:17-19`), and must be applied per iteration. Priority Tier cost is not in Anthropic's cost report, so only the gateway sees it.
8. **Cache TTL buckets**: cache writes cost 1.25x (5m) or 2x (1h) of input; reads 0.1x, 0.05x on Opus/Sonnet 5.5 ([pricing](https://platform.claude.com/docs/en/about-claude/pricing#prompt-caching), [#26 table](https://github.com/jeiang/atrium/blob/research/claude-models/research/claude-models.md)). Map `cache_creation.ephemeral_{5m,1h}_input_tokens`; if only the aggregate exists, `tokens_of` assigns the remainder to 5m (`usage.py:20-32`).
9. **Unknown model id**: fail closed. Price at the highest known rate and flag the row `unpriced`, never at zero. Gateway aliases from Claude Code `/v1/models` discovery are possible ([gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)); decide whether to serve that endpoint.
10. **Errors and aborts**: non-2xx has no usage and costs nothing except mid-stream refusals: "a mid-stream refusal bills the input tokens and the output already streamed", and refusals before any output are billed in certain categories ([refusals: how refusals are billed](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback#how-refusals-are-billed)). An SSE `error` event after `message_start` (for example `overloaded_error`, [streaming errors](https://platform.claude.com/docs/en/build-with-claude/streaming#error-events)) or a downstream abort ends the stream with no final usage. Record what was seen (`message_start` input plus last cumulative output) with `partial=1`; Anthropic's treatment of client-aborted generations is not stated in the docs I read `[unverified]`, so reconcile through the Admin API. Choice on downstream abort: cancel the upstream request (stops further spend, loses the final count) vs drain it to `message_stop` (exact, but continues to pay). Recommend cancel on abort and drain only on gateway-initiated stops that need exactness `[inference]`.
11. **Retries and duplicates**: dedupe on the upstream `request-id` response header; the gateway should not retry upstream itself for streamed requests; Claude Code retries (`x-should-retry`, `retry-after` semantics in the gateway protocol) arrive as new requests with new ids and are legitimately new spend.
12. **Fallback**: server-side fallback adds a `fallback_message` iteration; the refused attempt can itself be billed; fallback credit adjusts the retry price, so token tally x list price slightly overstates ([fallback credit](https://platform.claude.com/docs/en/build-with-claude/fallback-credit)). Conservative; document it and let reconciliation show the delta.
13. **Path allowlist**: only `POST /v1/messages` (`?beta=true`), `POST /v1/messages/count_tokens` (not recorded; the endpoint ignores `compaction` and is "free" per #25), `GET /v1/models`. Reject Files, Batches (50% priced), Skills, and anything under `/v1/organizations`. This closes bypass routes that would evade metering.
14. **Transport**: forward `anthropic-version`, `anthropic-beta` verbatim, relay SSE incrementally including `ping`, forward upstream error bodies unmodified and `anthropic-ratelimit-unified-*`, `retry-after` (integer seconds), `x-should-retry` ([gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol#streaming)). Request upstream with `Accept-Encoding: identity` or decode it before parsing. Tee the stream into the parser; parsing must never block relaying.
15. **Persist per request**: ts, sandbox/thread/run, agent kind, `request-id`, `anthropic-workspace-id`, model, per-iteration tokens, searches, tier/speed/geo, computed cost, `partial`, `unpriced`, and the agent's headers (`x-claude-code-session-id`, request class, agent id).

### 4.3 Worst-case size of one request (for admission control)
At list prices the maximum a single request can cost is bounded by context and `max_tokens` (1M context and 128K max output on all 5.5 models, #26 section 2). Using [pricing](https://platform.claude.com/docs/en/about-claude/pricing#model-pricing): Opus 5.5 ~ 1M x $8 (1h cache write) + 128K x $20 ~ **$10.6**; Sonnet 5.5 ~ 1M x $4 + 128K x $10 ~ **$5.3**; Haiku 5.5 over 100K ~ 1M x $1 + 128K x $2.50 ~ **$1.3** (my arithmetic). The 5.5 context is large enough that "one more request" can exceed the whole per-delegation cap suggested in #32 ($2). Admission control therefore needs a reservation, not a post-hoc check.

## 5. Hard caps and kill switches

### 5.1 Layers, from tightest to loosest

| Layer | Scope | Enforcement | Overshoot | Applies to |
|---|---|---|---|---|
| L1 gateway admission with reservation | per request | before forwarding, reserve `est_input_tokens x input_rate + max_tokens x output_rate` from the thread/run cap and from the monthly budget; refuse if remaining < reservation; release/settle at `message_stop` | bounded by estimate error (parallel subagents each hold their own reservation) | API-key agents (pi, Claude Code API mode) |
| L2 gateway running totals | per sandbox / thread / run / month | atrium `budget.check` equivalent (`budget.py:32-40`) plus per-thread cap; 80%/100% thresholds as today | one reservation per concurrent request | same |
| L3 gateway mid-stream stop | per request | cancel upstream when cumulative `output_tokens` x rate crosses the remaining cap | tokens already generated | same |
| L4 revoke bearer | per sandbox | delete the per-sandbox token; next request 401; Claude Code surfaces an auth error | none after revocation | same |
| L5 manager kill | per sandbox | SIGINT, grace, SIGTERM (#32 section 3.1 semantics), then suspend/kill the microVM; drop the vsock/relay | in-flight request only | all, including subscription and local-model runs |
| L6 client flags | per agent run | Claude Code `--max-budget-usd` (estimate; "spend can pass the cap by up to the cost of that one response" plus running subagents), `--max-turns`, `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`; pi: atrium sends `abort` on `message_update.usage.cost.total` (#32) | one response | per agent |
| L7 wall clock and idle timeout | per run | manager timers | n/a | all |
| L8 Anthropic workspace/org spend limit and rate limits | per workspace/org, monthly | Console only; breach returns HTTP 400 `invalid_request_error` ("You have reached your specified workspace API usage limits") ([rate limits](https://platform.claude.com/docs/en/api/rate-limits#setting-your-own-spend-limit), [errors](https://platform.claude.com/docs/en/api/errors)); tier cap returns 429 until the 1st 00:00 UTC | the whole month | backstop |

Sources for L6: [agent loop: turns and budget](https://code.claude.com/docs/en/agent-sdk/agent-loop#turns-and-budget), [subagents: cap depth, concurrency, spend](https://code.claude.com/docs/en/agent-sdk/subagents#cap-subagent-depth-concurrency-and-spend), [cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking) (estimates, "not authoritative billing data"; `usage` excludes subagents, `total_cost_usd` and `modelUsage` include them).

### 5.2 What the gateway should return when it refuses
Claude Code reads error bodies and retry headers: `retry-after` above 60 s "stops the retries and shows the error at once" outside the retry-watchdog mode, and `x-should-retry` is passed through ([gateway protocol: response headers](https://code.claude.com/docs/en/llm-gateway-protocol#response-headers)); error bodies must stay Anthropic-shaped or its recovery logic misreads them ([automatic retry](https://code.claude.com/docs/en/llm-gateway-protocol#automatic-retry-and-error-forwarding)). `[inference]` Return an Anthropic-format error (`{"type":"error","error":{"type":"rate_limit_error","message":"atrium: thread cost cap reached ..."}}`) with 429, `retry-after: 3600`, `x-should-retry: false` for a hard stop, and verify with a recorded run that Claude Code stops rather than loops (candidate ticket 3). Do not map to 400 (Claude Code treats some 400s as capability rejections and retries without the feature).

### 5.3 Caps to expose
- Instance: monthly budget (exists, default $150 in v2), 80% scheduled / 100% chat (plan).
- Thread: `thread_cost_cap_usd` (default from the environment or a new setting), checked in L1/L2; also run ceiling (today `MAX_RUN_COST_USD = 2.0`, `loop.py:23`) and child ceiling (`CHILD_MAX_COST_USD = 0.25`, `subagents.py:9`). For `code_agent` delegations pass `--max-budget-usd` equal to the remaining thread cap minus a margin of one worst-case request.
- Environment: `max_concurrent_requests` (reservation fan-out) and `max_output_tokens` clamp. The gateway can lower `max_tokens` in the request body before forwarding `[inference: this mutates the body; Claude Code/pi must tolerate a shorter completion; test]`.
- Anthropic backstop (docs, UI-only): workspace spend limit for the sandbox workspace.

### 5.4 Bypass risks
- The VM holds only a placeholder key and the gateway bearer, so API traffic cannot avoid the gateway if egress is closed to `api.anthropic.com` (#25 allowlist). In subscription mode `api.anthropic.com`, `claude.ai` and `platform.claude.com` are open ([network access](https://code.claude.com/docs/en/network-config#network-access-requirements)); the traffic is direct and unmetered by design.
- A bearer is bound to a sandbox; bind it to the tap/vsock identity as #25 suggests so a leaked bearer from another VM is rejected.
- Out-of-band keys: if the owner puts a real Anthropic key into environment secrets (runtime secret), the gateway is bypassed; warn in the secrets UI, and the unattributed-spend alert in section 2.3 catches it.

## 6. Subscription Claude Code runs: what the operator can see

Policy recap (details in #32/#25): an end user signing in to the unmodified binary with their own subscription is allowed "including where a platform hosts Claude Code"; developers "may not collect, store, or intermediate Claude.ai credentials or session tokens" ([legal and compliance](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)); the "advertised usage limits ... assume ordinary, individual usage" ([same page](https://code.claude.com/docs/en/legal-and-compliance#acceptable-use)). Also supported: customers provisioning their own API keys for their own authorized users, billed to the key owner ([same page](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)), which is the gateway-injected key model. Consequences for metering: a gateway that forwards the subscription OAuth bearer (possible per the gateway doc) would intermediate the credential, so I recommend that atrium never sit in the subscription request path (#25 option 3 stays "do not build").

### 6.2 What to show
A "Claude subscription" card on the usage page, separate from the budget gauge, with the label "not metered against the monthly budget":
- Runs this month, API-equivalent value (sum of `total_cost_usd` deltas), tokens by model (from `modelUsage`), last `rate_limit_event` (status, utilization %, resets at), count of `credits_required` events, token expiry (one-year `setup-token`, or the 3-day-before-expiry warning for a stored login, #32 section 3.4).
- A warning when usage credits could bill the owner: with usage credits on, work past the plan limit is billed at API rates, with an optional monthly spend limit the owner sets in claude.ai ([costs: usage credits](https://code.claude.com/docs/en/costs#add-usage-credits-to-your-subscription)). Atrium cannot see that spend; tell the owner to set a limit there or leave credits off.
- Ledger rows: `source='claude_subscription'`, `cost_usd=0` for budget math, `equiv_cost_usd` for display, optional `plan_utilization`.

### 6.3 Limiting subscription runs
Atrium can only: choose whether subscription mode is enabled per environment; pass `--max-turns` and `--max-budget-usd` (on estimates; it does bound token volume); wall clock and idle timeouts; stop and kill on `rate_limit_event.status == "rejected"` or when OTel-reported equivalent cost for the session exceeds the thread cap (advisory); keep it chat-only (#32 recommendation). Plan windows are the real cap, enforced by Anthropic.

## 7. Options and trade-offs

| Decision | Options | Trade-offs | Recommendation |
|---|---|---|---|
| Metering source for API-key agents | gateway ledger / Admin API polling / client-reported cost | Gateway is real time and per thread; Admin API is authoritative but 5+ min late, org-only, no thread; client cost fields are estimates | Gateway ledger, Admin API optional reconcile |
| Where the gateway runs | atrium host / manager | #25: atrium host keeps the key off the remote manager | Atrium host (confirm in #25 follow-up); manager relays with the bearer |
| Streaming abort | cancel upstream / drain | cancel stops spend, loses exactness; drain keeps exactness, keeps paying | cancel, mark `partial`, reconcile |
| Cap check | post-hoc total / reservation | post-hoc can overshoot by up to ~$10 per Opus request and N parallel requests | reservation + settle |
| Refusal signal to agents | 429 + `x-should-retry:false` / 402 / 400 | 400 risks capability-retry logic; 429 is documented as "stop" if retry-after > 60 s | 429, verified by fixture |
| Anthropic workspace layout | single workspace / loop + sandbox workspaces | two workspaces add a backstop and a clean Admin split but need an org and a multi-workspace key | single default; document two as optional |
| Subscription metering | none / stream-json only / + OTel receiver | OTel adds a listener and an egress path; richer but not enforceable | stream-json always, OTel opt-in |
| Budget semantics for subscription | count equivalent $ against budget / separate | counting would pause the instance for usage Anthropic does not bill | separate, labelled |

## 8. Risks
- Gateway parsing drift: new usage fields and iteration types appear with betas (`fallback_message` and `advisor_message` are recent); an unmodelled type must be priced conservatively and flagged, not dropped. Golden streams per Claude Code/pi/SDK version.
- Partial-stream undercount and fallback credit overcount; both bounded but real; reconciliation shows them.
- Reservation estimates: input size must be estimated before the call; a low estimate lets an expensive request through. `count_tokens` is available but adds a round trip `[inference]`.
- The gateway becomes a single point of failure and a SPOF for latency (streaming idle watchdog trips if pings are buffered, [gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol#streaming)).
- A key with Admin-level reach (multi-workspace personal key) is more powerful than a workspace key; do not reuse the Admin credential as the inference key.
- Month-boundary mismatch (local vs UTC) can make the 80% gate and Anthropic's tier cap disagree for a few hours.
- Policy drift on subscription use; keep nothing dependent on it (#32).
- `usage.run_id` is `NOT NULL REFERENCES runs(id)` (`src/atrium/agent/schema.py:66-82`); traffic from a sandbox outside a run (for example an interactive attach) has no run.
