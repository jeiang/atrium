## Answer

**Yes: every feature the Python loop uses is typed in the Go SDK. One thing is not possible: byte-identical request bodies from the typed params.** The SDK sorts JSON keys alphabetically, so the typed path can only be made *semantically* identical. If goldens must be byte-exact, serialize the body ourselves and hand it to the SDK as a raw body (supported, details below).

## Gaps and behavioural differences that matter for the port

1. **Streaming helper API differs.** Python's helper synthesizes `thinking`/`text` events and a `content_block_stop` event carrying `.content_block` (`progress.py:110-130`). Go gives only raw events: `content_block_stop` has just `Index` (`betamessage.go:15136`). To reproduce `Writer.observe`, call `msg.Accumulate(ev)` first, then on `content_block_stop` read `msg.Content[ev.Index]` (server_tool_use / web_search_tool_result / `*_code_execution_tool_result`); take deltas from `ev.Delta.Type == "thinking_delta"|"text_delta"` (`.Delta.Thinking`, `.Delta.Text`). There is no `get_final_message`: the accumulated `BetaMessage` is the final message after `message_stop`. `Accumulate` returns an error on out-of-order block indices; treat as a stream failure.
2. **Request bodies are not byte-identical to Python (cannot be, with typed params).** `internal/apijson/encoder.go:262-264` sorts struct fields lexicographically; map keys are sorted at `:347`; `requestconfig.go:150` and `MarshalJSON` paths HTML-escape strings (`<`, `>`, `&` become `\u003c...`). Python (httpx via the Python SDK, [inference]: `json=` with insertion order, compact separators, `ensure_ascii=False`) keeps the dict order. Keys such as `stream` are appended last by `WithJSONSet("stream", true)` (`betamessage.go` NewStreaming).
3. **`BetaToolParam.Type` is omitted when unset; `BetaToolInputSchemaParam.Type` always `"object"`.** Matches what Python sends today only if our tool dicts have no `type: custom`; check in golden diff.
4. **Struct-pointer schemas are rewritten** (see structured outputs row). Never pass a struct for `notion_migrate`'s schema if parity with the authored schema matters.
5. **Defaults to align:** SDK default request timeout 10 min (`client.go:308`), 2 retries; `thinking_warn.go` only warns for `thinking.type=enabled` on old models (irrelevant for adaptive).
6. **`web_search_20260318` default `allowed_callers`** is `["code_execution_20260120"]` (dynamic filtering) when omitted, server-side, for both languages ([docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)); behaviour is the same as today, but when the sandbox replaces Anthropic code_execution (Phase B) set `AllowedCallers: ["direct"]` deliberately.

## Golden tests: options for body fidelity

Existing Python tests assert on the **params dict** passed to a fake client (`tests/fake_anthropic.py:86-96`), never on bytes. So the porting contract is "same request content", not "same bytes", unless we decide otherwise.

| Option | How | Pros | Cons |
|---|---|---|---|
| A. Typed params, canonical-JSON goldens (recommended default) | Build `BetaMessageNewParams`; in tests run an `httptest` server (or `option.WithHTTPClient` with a recording `RoundTripper`/`option.WithMiddleware`) and compare the body to the golden after canonicalization (decode+re-encode with sorted keys, e.g. `jq -S`); generate Python goldens with `json.dumps(sort_keys=True, ensure_ascii=False)`. | SDK validation, union types, forward compat; small code. | Not byte-equal; relies on both sides parsing to the same JSON. |
| B. Own body encoder + `option.WithRequestBody("application/json", bytes)` | Atrium builds an ordered request struct/`map` -> bytes (`encoding/json` with `SetEscapeHTML(false)`, struct order = Python dict order). Pass `BetaMessageNewParams{Betas: ...}` (only to get the header; the body is replaced) plus `WithRequestBody`. `NewRequestConfig` marshals the params first and `WithRequestBody` overwrites `r.Body` (`requestconfig.go:89-154`, `requestoption.go:352-370`); `NewStreaming` then adds `"stream":true` via sjson on the buffer (`betamessage.go:128`). Still get retries, auth headers, SSE decoding, `Accumulate`, typed responses. | Byte-identical goldens are achievable (also stable prompt-cache prefix: bytes equal run to run). | We own the request schema (no compile-time checks); must keep it current as betas change; `WithJSONSet` on non-buffer bodies errors. |
| C. Raw HTTP | `net/http` POST `/v1/messages?beta=true` + own SSE parser + own accumulator. | Total control. | Re-implements retries, SSE, accumulation, errors; needs compaction/server-tool delta handling (`compaction_delta`, `citations_delta`, `signature_delta`) by hand. Not justified. |
| D. Hybrid | A for `NewParams` building in app code; one thin helper that marshals the typed params with the SDK (`json.Marshal(params)`) then re-encodes through an ordered pass if a byte golden is required. | Keeps types. | Extra code; ordering rule still needs spec. |

Note on cache stability: sorted-keys output is deterministic across requests, so prompt-cache prefix matching is unaffected by key order (the cache keys on content, and our output is stable run to run). ## Recommendation (ties to plan: Phase A = as-is port, Go, Anthropic key per instance)

1. Adopt `anthropic-sdk-go` v1.82.0 (pin; update via renovate) for all Anthropic calls: `Beta.Messages.NewStreaming` for the loop, `Beta.Messages.New` for compaction summary and Notion migration, `client.Files` for the Files API. Build one `anthropic` adapter package exposing `Stream(ctx, req) (*BetaMessage, error)` that hides Accumulate and emits `progress` events from the accumulated message at `content_block_stop`.
2. Keep Phase A on the existing `compact_20260112`/`context-management-2025-06-27` betas (identical request to Python). The server now also offers on-demand compaction (`compact-2026-09-04`, top-level `compaction`, `BetaMessageNewParams.Compaction`, [docs](https://platform.claude.com/docs/en/build-with-claude/compaction)); evaluate it in Phase B only (ticket below).
3. Contract for "identical requests": canonical-JSON equality (Option A). Generate goldens from the Python app by recording request params with sorted keys, and diff in Go via a recording `http.RoundTripper`. Reserve Option B only if the owner wants byte-for-byte goldens or if a field the SDK cannot yet express appears; the escape hatches (`param.Override`, `WithJSONSet`, `WithRequestBody`) cover it with no fork.
4. Journal content blocks as raw JSON (`block.RawJSON()`), replay them via `ToParam()` / `param.Override[BetaContentBlockParamUnion](raw)`; this reproduces Python's `model_dump(exclude_unset=True)` replay including unknown block types.
5. Tool schemas: keep authored JSON Schema as `map[string]any`/`json.RawMessage`; fill `BetaToolInputSchemaParam.Properties/Required` and put the rest in `ExtraFields`.

## Risks

- **SDK churn:** 82 minor releases; beta type names embed dates (`BetaCompact20260112EditParam`); a release can rename or remove them. Mitigation: pin, wrap in the adapter, golden tests catch drift. Go SDK pulls `invopop/jsonschema`, `tidwall/sjson` etc. (check dependency/licence footprint in the licence ticket).
- **Beta deprecation:** `compact-2026-01-12` is documented but a newer compaction beta exists; Anthropic may retire the older one [inference: no retirement notice found in the pages read].
- **Mid-stream failures:** neither SDK retries a stream after bytes arrive; atrium's journal must stay idempotent per request exactly as in Python.
- **Struct-pointer schema rewrite** silently changes schemas.
- **`Accumulate` strictness** (index gaps return errors) is stricter than Python's helper.
- **Files API:** uploaded files kept up to 30 days (`files.py:48-53` notice), no SDK difference.
