# Integrations

Every connection is configured and tested on the Connections page
(`/settings/connections`) or declared under `connections` in the host
configuration. A provider
credential is stored write-only in an encrypted database or supplied by the
connection's `credential_files` entry in the host configuration; there is no
environment pin for a secret. The only environment secret inputs left are the
database key (`ATRIUM_DB_KEY`/`ATRIUM_DB_KEY_FILE`) and the two app key files
(`app_keys.action_link_key_file` and `app_keys.link_key_file`), which the
NixOS module's `secretFiles` option renders. The matrix is the support
summary; the sections below cover the console work atrium cannot do for you.

## Capabilities and dependencies

Each connection kind offers the capability names its test reports, and each
module declares the capabilities it needs, with the features that stop or
degrade without them. A hard need blocks its features; a soft need degrades
them. A connection serves a capability when it is enabled and that
capability row is enabled; a row that lists none of its kind's capabilities
serves all of them. When several connections serve a need, atrium binds the
first healthy one in id order (`ok`, `expiring`, `away` or `untested`), or the
first one when none is healthy.

`GET /api/v1/connections/dependencies` returns every need with its binding,
candidates, state and availability, and every open repair. A repair is
derived from a connection in `needs_reauth` (class `auth`), `failing`
(`unreachable`) or `unconfigured` (`config`); its id is
`connection:<id>:<class>`. A repair lists the features of unmet active needs
that the connection could serve, and its severity is `blocker` for a hard
need, `degraded` for soft needs only, and `notice` otherwise. A disabled
connection has no repair, and neither does an idle one. Each connection in
`GET /api/v1/connections` lists its `dependents`; when it has dependents and
none of their apps is on, an enabled connection also shows
`idle: "its app is off"` and is not checked on schedule. Built-in connections
atrium creates itself are disabled with that reason instead, and come back as
`untested` when an app that needs them is turned on.

## Google

Google Calendar and Gmail use a Web-application OAuth client that each
instance registers itself. The wizard on the Connections page stores the
client ID and secret, performs one consent per capability, and keeps the
refresh token as a write-only secret in the database.

| Account | Gmail IMAP and SMTP | Calendar | Notes |
|---|---|---|---|
| Personal | App password or XOAUTH2 | OAuth | An app password needs 2-step verification and Google does not recommend it |
| Workspace | XOAUTH2 | OAuth | App passwords are not available |
| Advanced Protection | XOAUTH2 | OAuth | App passwords are refused |

The Gmail consent in the wizard stores a refresh token for the XOAUTH2 mail
transport. Add the Gmail account on the Mail settings page and choose
XOAUTH2; a personal account may use an app password instead.

### Setup

1. Open [Google Cloud credentials](https://console.cloud.google.com/apis/credentials)
  and create a project, or pick one.
2. Configure the [OAuth consent screen](https://console.cloud.google.com/apis/credentials/consent)
  as External, then add your own address as a test user.
3. Enable the [Google Calendar API](https://console.cloud.google.com/apis/library/calendar-json.googleapis.com).
  Gmail over IMAP and SMTP uses the `https://mail.google.com/` scope and
  needs no Gmail API.
4. Create credentials of type **Web application** and add the redirect URI
  `https://<atrium-host>/settings/connections/google/callback`.
5. Paste the client ID and secret into the Google wizard, then connect
  Calendar and Gmail separately.

If Google rejects the redirect URI, register the same path on a host you
control, or use the paste-back box with any registered URI.

### Testing mode

An External project in **Testing** issues refresh tokens that expire after
7 days. Publish the app to **Production**; personal use under 100 users does
not need verification or CASA, and the unverified screen is expected. A
token also dies on revocation, after 6 months unused, on a password change
for the Gmail scope, or when an administrator policy revokes it. Unused
OAuth clients are deleted after 6 months.

Calendar uses `https://www.googleapis.com/auth/calendar.events`; the narrower
`calendar.events.owned` does not suffice because the calendar lists existing
events. Gmail uses `https://mail.google.com/`. Each instance brings its own
client; do not share one.

## iCloud

iCloud has no third-party developer registration. The only method for IMAP,
SMTP, CalDAV and CardDAV is an app-specific password:

- Create it at [account.apple.com](https://account.apple.com); it needs
  2-step verification.
- One password covers all four protocols. At most 25 exist at once.
- It is revoked when the Apple Account password changes.
- Atrium can accept, test and store it, but cannot create it.

Mail accounts come from `accounts`; calendar and contacts reuse an iCloud
mail account for their CalDAV and CardDAV login through one shared `icloud`
connection that neither module owns: turning calendar or contacts off leaves it
enabled for the other, and a rejected password marks both capabilities for one
repair. The Calendar section on the
Calendar settings page (`/settings/calendar`) edits `calendar_account`, `icloud_apple_id`, `icloud_calendar`,
`default_event_minutes`, `work_hours` and `work_days`.

Discovery asks the DAV root for the current user principal and the home set in
one request. iCloud answers the root on the partition that accepted the
password and names it in the `X-Apple-User-Partition` header. When the
principal or the home set on another host refuses the password, discovery
repeats that request once on the named partition host (`pNN-` before the
configured host name, for example `p7-contacts.icloud.com`). When the
principal is still refused, discovery retries from `/.well-known/caldav` or
`/.well-known/carddav` and follows at most 3 redirects. The credential goes only
to the configured DAV host and, over https on the same port, to a sibling host
under the same parent domain, such as an iCloud partition host. Atrium refuses
any other redirect, principal, home set or collection address without sending
the credential, and logs the step, status, host class and challenge of each
failed DAV request.

A sync remembers, in memory, the home set and the collections it found for
each capability, DAV address and credential, and goes straight to the
collections on the next run, listing the home set again at most once an hour.
It discovers again from the root only when a remembered address answers 401,
403, 404 or 410, or when the credential or address changes; a restart forgets
everything. A contacts sync is therefore one `REPORT` per address book, with
one extra `PROPFIND` an hour. The silent health check of the iCloud
connection reuses the result of a sync of the same capability from the last 20
minutes and sends nothing; while a sync of that capability is running it keeps
the stored result, and otherwise it lists the remembered home set again (one
`PROPFIND`). The explicit `connections test` and `--trace` always discover
from the root. A refusal, HTTP 429 or HTTP 503 pauses every request for that
capability for 1, 3, 6 and then 12 hours, as described in
[behavior](operator/behavior.md).

## Knowledge export

The knowledge base is written to one Markdown folder by the daily
`knowledge-export` job. The **Markdown export** section on the Export settings
page (`/settings/export`) shows the folder (`export_obsidian_dir`, declared by
the host through `services.atrium.knowledgeExport.obsidianDirectory`) or "Not
configured"; its private switch stores the folder path in
`export_obsidian_private_to`. The job fails while no folder is set or the
folder cannot be written. The export overwrites the files it tracks on every
run and removes the file of a record that is retracted or leaves the export
set. A write with an unknown outcome blocks the export until it is resolved.

## Grafana

Create a service account in Grafana and paste its token. The Viewer role is
enough: it can query datasources. A token has no expiry by default; set a
TTL if your policy requires one. The Test button searches dashboards and
reports a token that may not search as needing the Viewer role. The
Connections page edits the URL and the token; the datasources come from the
host configuration under `connections."service/grafana".config`
(`metrics_uid`, `logs_uid`, `logs_type` and `logs_query`).

## Anthropic

Use a Console API key from a workspace dedicated to this instance, with a
monthly spend limit, so a leaked key cannot spend beyond it. A key can be a
personal, service-account or legacy workspace key; it is workspace-bound and
may carry an expiry.

- Rotate the key in the Console and paste the new one on the Anthropic
  connection on the Connections page; the old key stops working.
- The key is stored encrypted in the `service/anthropic` connection, or the
  host supplies it through `credential_files.api_key`; a key from the host
  file cannot be changed from the UI.
- An Admin API key can list members, workspaces and usage cost, but cannot
  mint keys. Atrium does not use one yet.
- Subscription OAuth is not allowed for third-party products; only the
  unmodified Claude Code binary signs in to a subscription itself.

## Mail endpoints

The embedding endpoint is the `service/embedding` connection: an
OpenAI-compatible base URL ending in `/v1`, with an optional host-file bearer.
Its Test lists models and measures the dimension. A hosted endpoint warns that
mail content leaves this host. Mail classification has no chat endpoint; it
uses fixed-schema Haiku requests through the `service/anthropic` connection.

## qBittorrent

Create an API key in qBittorrent 5.2 or newer and paste it, or declare
`credential_files.api_key` on the host connection. Every request carries the
key as a Bearer token, so there is no session to expire. Without a key,
requests go unauthenticated, which works only while qBittorrent bypasses
authentication for atrium's address. A refused request marks the connection
`needs_reauth`: "qBittorrent requires an API key" when none is configured,
"qBittorrent refused the API key" when the key is wrong. Test fails on a
server older than 5.2, which has no API keys.

## TMDB

Create an API read access token in your TMDB account settings and save it on
the `/settings/connections` TMDB record. Every request carries it as a Bearer
token, never as a query parameter, and it is never sent to the image host.
Test reads `/configuration` and then checks the image host without the token.
The API and image URLs come from `connections."service/tmdb".config` in the
host configuration. Media pages that show TMDB data carry the attribution.
VPN library links use one base, `host.media.media_vpn_base_url`, served by the
media agent's `[vpn]` listener; the retired `media_movies_url` and
`media_tv_url` host keys are refused.

## Open-Meteo

Weather forecasts and place lookup need no credential. The location is the
operator settings `weather_latitude`, `weather_longitude` and optionally
`weather_location_name`, in the Weather group of the Assistant settings, the
weather connection in `/next/` Settings › Connections, `atrium settings set`
or the host file. The `weather` tool reads them, or
geocodes a place named in the call. Latitude must be between -90 and 90 and
longitude between -180 and 180. The tool fetches only
the configured Open-Meteo hosts, and the request carries no operator data
beyond the coordinates.

## Ship24

Ship24 supplies live package tracking for the opt-in Packages app
(`packages_enabled`), for packages the operator registers with the
`track_package` tool or `POST /packages/{package_id}/track`. Create an API key in the Ship24 dashboard and
paste it on the Connections page, or declare `credential_files.api_key` on
the `service/ship24` connection in the host configuration. The free plan registers 10 shipments a month; the
compiled quota `tracking.TuningMailShip24MonthlyQuota` (10) refuses further
registrations once the month's count is exhausted. Atrium polls the active
trackers hourly and stops polling delivered packages. There is no webhook
route.

## EZTV

EZTV's public API supplies the media channel episode lists. It needs no
credential. Test fetches one bounded indexer response (`limit=1`) and checks
its shape without adding a torrent. Media writes touch only torrents tagged
media.

## OIDC presets

Set the preset in the host configuration as
`connections."service/oidc".config.preset`; the Sign-in settings page shows
the configuration read-only. A host that names any other preset fails at
start with a configuration error.

| Preset | Name | Issuer | Scopes | Groups claim | Notes |
|---|---|---|---|---|---|
| Pocket ID | `pocket_id` | Issuer URL | openid profile email groups | groups | Enable PKCE; allow the access and admin groups |
| Generic OIDC | `generic` | Issuer URL | openid profile email groups | groups | Confidential client with PKCE S256 |
