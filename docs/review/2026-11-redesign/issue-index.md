# Issue index

One row per issue for [implementation-plan.md](implementation-plan.md). Each phase has one epic (`P<n>.0`), and each slice is one agent session and one pull request. Source ids follow the plan's legend: D, R, N and C ids, report findings `r1` to `r6`, `rev` items of research notes: `plan/review.md`, coordinator rulings, and file:line.

Every atrium path listed was checked to exist in the atrium repository. A path marked `(new)` does not exist yet and is created by the slice. Paths starting with `cornn-flaek/` are in the host repository.

The GitHub issue numbers are assigned in the order of the table below, epics first; the issues for the first trains were opened earlier and come before the rest. Each issue links back to this index.

**Ids.** Ids from the first version are kept. A slice folded into another has no row: P0.3 is in P0.2, P1.2 is removed (ruling 2), P3.8 is in P3.3b, P6.1 is in P6.2, P10.4 is in P10.1, P12.4 is in P12.3, and P16.2 is in P16.1. A split slice becomes `a` and `b` rows. P0.11 is new.

**Sizes:**

- **S:** up to about 300 changed lines excluding generated files, or a pure deletion; under half a session.
- **M:** about 300 to 1,200 lines, or a deletion up to about 3,000 lines; one session.
- **L:** about 1,200 to 3,000 lines, a larger deletion, or a whole-subsystem move; one full session and one pull request.
- An epic has no size.

**Labels** come from the repository's existing set: `build`, `slice`, `bug`, `enhancement`, `documentation`, `accessibility`, `question`, `wayfinder:research`, `wayfinder:prototype`, `wayfinder:blocked`, `post-cutover`.

**Every slice runs:**

- `just verify` during work
- `just e2e '<pattern>'` for the named workflow
- `just check-quick` before hand-off (includes `tableownership`)
- `just check-eval` after Nix changes
- `just check` before the pull request

Web slices from P4.6a on also run `web-e2e`, and from P4.6b `web-size` and `web-lighthouse`. Slices marked "(mail)" run `just e2e 'Mail|Live|Replay|Serve|Snooze'` before and after and deploy with the mail net (plan section 8.5). No merge while `main` CI is red. A slice stops when its acceptance holds, or at a stop point in plan section 6.2.
